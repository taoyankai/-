# 快递100物流接入

项目使用企业版“实时快递查询”。凭据仅在服务端私有配置中保存，不能放入前端、日志、截图或 Git 仓库。

## 配置与发布

本机生产配置为 `deploy/server/.env.production`；服务器配置为 `/home/ubuntu/.config/hz-delivery/server.env`。根目录 `.env` 是另一套本地配置，不会自动同步到生产环境。

```ini
LOGISTICS_PROVIDER=kuaidi100
KUAIDI100_KEY=从已开通账号取得的授权KEY
KUAIDI100_CUSTOMER=从已开通账号取得的CUSTOMER
LOGISTICS_QUERY_ON_ACCESS=true
LOGISTICS_VALIDATE_ON_SHIP=true
LOGISTICS_MIN_INTERVAL_MINUTES=30
```

变更配置后需重建后端容器读取环境变量；单纯 `docker restart` 不会重新读取配置。代码更新仍通过 GitHub 标签发布和服务器指定版本构建完成。普通更新保留数据卷，不重新执行建表或演示脚本。

## 承运商与演示数据

当前支持顺丰 SF、京东 JD、圆通 YTO、中通 ZTO、申通 STO、邮政 EMS、韵达 YD。`YD` 映射为平台编码 `yunda`，见[官方编码列表](https://api.kuaidi100.com/document/Kdlist)。新库初始化包含韵达；已有库启动时只补齐缺失的 YD，不覆盖已有承运商资料。

保留前缀 `DEMO` 用于演示订单、人员工号和演示运单，忽略大小写及首尾空白。查询、批量查询、定时刷新和查询适配器均阻断演示记录调用真实平台；定时批次还在取数时排除演示记录，避免占满真实订单批次。演示订单或演示运单不能用于真实发货，即使临时关闭发货校验也会拒绝。

演示轨迹继续由数据库展示；真实查询不会覆盖或新增这些轨迹。现有 37 条停用演示名单不能用于真实短信登录。

## 验收与业务边界

先完成模拟接口回归，覆盖演示阻断、普通订单保留查询路径、限频及韵达响应解析；再检查线上实际容器配置和健康状态。取得用户授权的真实运单后，通过同版本服务端查询适配器执行一次查询，检查承运商、运单和轨迹；不为测试创建发货单，也不把真实轨迹写到演示订单。

配置存在和容器健康只说明已启用，不代表真实查询成功。凭据错误、额度不足、运单不存在、手机号缺失以及网络错误，均须如实记录实际返回，不可用演示轨迹当作真实验收。

发货前先核验承运商及运单；成功的查询响应复用落库，避免校验和同步各查询一次。真实订单的访问刷新、手动刷新和定时刷新共用 Redis 限频，同一运单至少间隔 30 分钟。已签收、已退回订单不继续后台轮询。

凭据取得方式见[官方说明](https://api.kuaidi100.com/document/shouquankey)。真实查询将按平台账号的服务规则使用额度，本项目不自动购买或续费。
