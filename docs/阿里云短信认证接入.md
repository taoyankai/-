# 阿里云短信认证接入

本次接入的是号码认证 PNVS 的 `SendSmsVerifyCode` / `CheckSmsVerifyCode`，Java SDK 为 `com.aliyun:dypnsapi20170525:2.0.0`。原 `AliyunSmsSender` 属于传统短信通道占位，未用于此次认证。

## 配置与切换

当前独立验证环境已切换为 `aliyun-pnvs`，完成用户指定号码的真实收码及云端登录核验；通知短信仍为 `mock`。`deploy/verify/.env` 为验证环境实际配置；服务器使用 `deploy/server/.env`。两者均不提交 Git。

先在阿里云号码认证控制台开通短信认证，准备该产品配套的签名和模板。为专用 RAM 用户授予 `dypns:SendSmsVerifyCode` 和 `dypns:CheckSmsVerifyCode` 权限，将 AccessKey 写入本地配置，不在聊天、截图或仓库中传递。

```ini
LOGIN_MODE=sms
SMS_AUTH_PROVIDER=aliyun-pnvs
MOCK_SMS_CODE=
ALIBABA_CLOUD_ACCESS_KEY_ID=填写本地密钥
ALIBABA_CLOUD_ACCESS_KEY_SECRET=填写本地密钥
ALIYUN_PNVS_SIGN_NAME=填写号码认证签名
ALIYUN_PNVS_TEMPLATE_CODE=填写号码认证模板
ALIYUN_PNVS_SCHEME_NAME=hz-client-login
SMS_AUTH_TEST_ENABLED=false

# 通知短信独立配置；mock 不会发送超时告警短信。
SMS_PROVIDER=mock
SMS_TEST_ENABLED=false
```

签名、模板必须与号码认证服务匹配；模板使用 `code` 和 `min` 变量。请求固定 `{"code":"##code##","min":"5"}`，由阿里云生成六位数字，有效期 300 秒、发送间隔 60 秒，新验证码覆盖旧验证码；不要求阿里云返回验证码。方案名称发送/核验一致，长度 1–20 字符。

选择 `aliyun-pnvs` 后缺少密钥、签名或模板会使后端启动失败，不回退到演示模式。`SMS_PROVIDER=mock` 不会使 PNVS 登录出现演示提示，`MOCK_SMS_CODE` 在 PNVS 下被忽略。

在项目根目录执行验证环境重建（先完成密钥和模板配置）：

```powershell
docker compose -p hz-verify --env-file deploy/verify/.env -f deploy/server/docker-compose.yml -f deploy/verify/compose.override.yml config --quiet
docker compose -p hz-verify --env-file deploy/verify/.env -f deploy/server/docker-compose.yml -f deploy/verify/compose.override.yml build api
docker compose -p hz-verify --env-file deploy/verify/.env -f deploy/server/docker-compose.yml -f deploy/verify/compose.override.yml up -d --no-build --wait --wait-timeout 240 api
docker compose -p hz-verify --env-file deploy/verify/.env -f deploy/server/docker-compose.yml -f deploy/verify/compose.override.yml up -d --no-build --force-recreate nginx
```

仅修改环境变量无需重新构建镜像，仍需用 `up` 重建 API 容器并重建 Nginx 以刷新上游地址；`docker restart` 不会加载新的环境变量。不要在屏幕输出完整 `docker compose config`，其中含密钥。

## 业务流程与 Redis

- 发送：名单资格 → Redis 原子占用 60 秒冷却 → 每日上限 → 认证服务发送。
- 登录：锁定检查 → 名单资格 → 云端核验 → Redis 原子消费本次会话 → 签发项目 Token。
- 只有 `Model.VerifyResult=PASS` 才算核验成功；`Code=OK`、`Success=true` 只表示 API 调用成功。
- 阿里云模式 Redis 只存本次流水号，不存验证码。与本地模式使用不同会话键；切换不会接受旧的本地验证码。
- 每个号码发送/核验共用 120 秒互斥锁。SDK 连接 5 秒、读取 10 秒且不自动重试；Redis 写入/消费检查锁所有权，避免旧请求覆盖新会话。同一会话最多签发一次 Token。
- 明确未受理发送则撤回冷却与当日额度；网络超时等结果未知时保留 60 秒冷却、当日额度和本次流水，避免重复发送，已收到短信的用户仍可尝试核验。
- 验证码错误或到期累计登录失败，达到 5 次锁定 10 分钟；云端异常或核验繁忙返回业务码 `1010`，不计入用户输错次数。无本地会话则拒绝核验，防止重放。
- 阿里云也会通过 SDK 异常返回 `isv.ValidateFail`（错误、过期或被覆盖的验证码）；此码按验证码不匹配处理，其他 SDK 错误仍按服务异常处理，禁止笼统地把全部异常当成验证码错误。

## 运维自检与真实验收

`GET /api/admin/sms/status` 同时返回通知通道、认证通道和各自自检开关，不返回密钥。

新增认证自检接口（仅 `admin` 角色，默认关闭，另受 `SMS_AUTH_TEST_ENABLED` 控制）：

- `POST /api/admin/sms/auth/send-code?phone=...`：经过名单、频控、每日限额后发送。
- `POST /api/admin/sms/auth/verify-code`：用表单参数 `phone`、`code` 核验，完整经过业务锁定；成功后立即注销自检 Token，只返回 `verified=true`。

原 `POST /api/admin/sms/test` 继续只测试通知短信，不能用它判断 PNVS 是否接通。正式用户继续使用原有 `/api/client/auth/send-code` 和 `/api/client/auth/login`，接口路径和参数不变。

真实验收需指定一个本人可接收短信的号码并加入有效名单，在 H5 登录页发送一次，确认收码、错误码拒绝、正确码登录与成功后重复提交失败。自检如临时开启，验收后关闭。真实发送会消耗阿里云额度；离线测试通过不能代替真实收码验收。
