# 服务器发布准备记录（2026-10-22）

## 故障分析

初次 SSH 连接先被本机执行权限限制阻断。取得网络执行权限后，服务器返回 `Permission denied (publickey,password)`，表明网络已通但原有公钥未获授权。后来通过交互终端使用密码登录成功，备份服务器原授权文件并追加项目专用公钥后，新的非交互登录已验证成功。私钥仅保存在本机用户目录，不进入仓库、不上传服务器。第一次尝试打开的本机密码窗口没有显示，具体原因未确认，不能归因于服务器密码或 Docker。

服务器直连 Docker Hub 曾连接超时。腾讯云 Registry 根地址返回 HTTP 200 只证明入口可达；配置加速后，进一步实际拉取 nginx、redis、mysql、maven、eclipse-temurin 五个镜像全部成功，才完成下载链路验证。Docker 重启前检查无运行容器，配置先验证再生效，未覆盖其他已有配置。

GitHub 的网络与仓库授权分开验证。服务器通过 HTTPS、HTTP/1.1 实际读取公开仓库 HEAD 并完成克隆，无需 GitHub 部署密钥；GitHub 官方 HTTPS 元数据中的 ED25519 指纹与 SSH 443 扫描结果一致。本机直连 GitHub 的 SSH 443 和 HTTPS 仍超时，因此本次本地发布使用自己的 Ubuntu 服务器作为 SSH 跳板。GitHub 私钥始终留在本机，专用配置放在被忽略的 `server/target/`，不修改全局 SSH 配置，也不关闭主机指纹校验。

GitHub 默认分支为 `第一次跑通能打开版本`，本地开发分支为 `确保每个人限领一份`。远端默认分支已经合并之前的业务变更，两者发布前基线代码树相同；默认分支额外包含合并记录。本次短信、目录整理和部署改造尚未提交，才是 GitHub 尚无这些改造的原因。发布前已取得最新远端历史并快进基线，避免覆盖之前的合并记录。

## 本次发布范围

- 保留现有前端、后端、微信小程序和云函数源码，以及已有的业务和权限修改。
- 登录验证码接入阿里云 PNVS，由云端生成、发送和校验；本地保留名单、频控、登录锁定、核验会话和一次性消费逻辑。
- 整理当前与历史文档，补充正式空库初始化脚本、统一 Docker 配置、2GB 资源限制和按版本部署脚本。
- 后台初始化日志不再输出初始密码。
- 私密环境变量、SSH 私钥、验证数据库、日志、编译缓存、镜像包和历史测试产物不上传 GitHub。

## 发布和验收

先完成后端单元与独立 Redis 集成测试、配置校验、Git 候选文件及密钥排查。之后将同一提交快进发布到现有开发分支和默认分支，创建不可移动的 `v1.0.0` 标签；若该标签已存在则另选新版本，不覆盖原标签。

服务器从 GitHub 获取该标签，核对提交 SHA，将私密配置独立保存到 `~/.config/hz-delivery/server.env`，再运行 `deploy/server/deploy-version.sh`。源码从 Git 标签导出，后端镜像在服务器构建，构建和健康检查通过后才记录成功版本。私密配置单独经 SSH 迁移，不放入 Git。

首次运行只绑定 `127.0.0.1:80`，通过 SSH 隧道验收 H5、后台、健康接口、正式空库、资源上限和短信认证配置。无需再次发送真实短信。公网 HTTPS 和微信端发布随后单独处理。最终部署成功以服务器 `~/hz-delivery/current-release` 和实际容器健康结果为准，本文是发布准备记录，不代替运行验收。
