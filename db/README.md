# 数据库脚本说明

## 两类初始化脚本

| 文件 | 内容 | 使用范围 |
| --- | --- | --- |
| `init-production.sql` | 与原脚本一致的 12 张表及 6 条承运商基础数据；无删表语句 | 正式环境的全新空数据库，统一 Compose 默认挂载此文件 |
| `init.sql` | 建表前删表，写入演示人员、套餐、公告、订单和轨迹 | 隔离演示数据库，原文件保留不改 |

正式脚本不预置人员、套餐、库存、公告、订单、轨迹或后台账号。应用启动时由 `DataInitializer` 补齐缺失的 `admin`、`operator`、`viewer` 账号，初始密码来自 `ADMIN_INIT_PASSWORD`，已有账号密码不会因此重置。

首次登录后台并修改密码后，录入正式套餐和公告，通过 Excel 导入正式人员名单，再开放领取。

## 执行时机

MySQL 镜像只会在数据目录为空、首次初始化时执行 `/docker-entrypoint-initdb.d/` 下的脚本。Compose 将 `init-production.sql` 只读挂载为 `01-init.sql`，命名卷 `hz-mysql-data` 保存数据库。

- 普通容器重建、代码更新、服务重启不重新初始化数据库。
- 修改初始化脚本不会修改已有数据库，也不会自动清除已有演示记录。
- 正式脚本用普通 `CREATE TABLE`，已有同名表会报错；它不是可重复导入的升级脚本。
- 不把原演示脚本导入业务库，不通过删除数据卷实现更新。

## 已有数据库与后续迁移

已有数据库继续使用原数据卷。上线前先确认其中是否仍有演示数据；清理或迁移需单独制定方案、备份并核对，不能靠切换初始化文件完成。

后续表结构变更应提供独立、带版本号的迁移 SQL，记录适用版本、执行顺序及恢复方法；本次未引入迁移框架，也未向任何数据库执行 SQL。应用当前已有的启动兼容逻辑继续由源码维护，不能代替今后的迁移方案。

若初始化中断，先查看 MySQL 日志及已创建的表，再决定恢复办法；已有数据时不要直接重新导入或删除卷。

备份方法见[部署手册](../deploy/server/README.md#数据库备份)。
