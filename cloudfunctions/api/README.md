# 云函数通道配置说明（免备案上线通道）

本文件讲清楚三件事：**为什么需要它**、**怎么配**、**出错了怎么查**。

---

## 一、为什么需要云函数（能省掉域名和备案）

小程序发布成体验版/正式版后，`wx.request` 直连后端受微信**服务器域名白名单**约束：

| 要求 | 说明 |
| --- | --- |
| 必须是 **HTTPS** | `http://` 一律被拒 |
| 域名必须完成 **ICP 备案** | IP 地址**不能**填进服务器域名 |
| 域名必须在小程序后台登记 | 「开发管理 → 开发设置 → 服务器域名」 |

也就是说，走直连就绕不开：**买域名 → ICP 备案（7~20 个工作日）→ 配 HTTPS 证书 → 后台登记**。

而 `wx.cloud.callFunction` 不同：**请求由云函数在腾讯云侧发起**，出网请求不受小程序域名白名单约束。
于是后端只要有一个**公网可达地址**（IP + HTTP 也行）就能用 —— **不需要域名，也不需要备案**。

本项目的云函数就是一个纯粹的转发器（`cloudfunctions/api/`），不含任何业务逻辑：

```
小程序  --wx.cloud.callFunction-->  云函数 api  --http-->  Spring Boot 后端
        （走微信私有协议，免鉴权）                （公网 IP 即可，无需域名/备案）
```

> 云函数只用 Node 内置 `http`/`https` 模块，**零第三方依赖**：
> `wx-server-sdk` 已改为**可选加载**（它只被用来调一次 `cloud.init()`，而本函数用不到
> 它的任何能力），因此**即使云端没装依赖也能正常转发**，部署秒完成。
> 对应地，`package.json` 的 `dependencies` 为空。

### 关于 `config.json`（一个必须说清的边界）

云函数目录下的 `config.json` **只能**声明两个字段：

| 字段 | 用途 |
| --- | --- |
| `permissions.openapi` | 云调用权限（本项目不用，留空数组） |
| `triggers` | 定时触发器（本项目不用） |

**环境变量和超时时间不在这里** —— 写了也不生效（实测过：`envVariables` / `timeout`
写进去，部署后既不生效也不报错）。官方文档把这两项归为**「环境配置」（type=3）**，
结构是 `{timeout, environment:[{key,value}]}`，**只能在云开发控制台配置**。

另外 `config.json` **不能写注释** —— 官方文档明确「配置文件里不能有注释」，
带注释会让解析失败、整份配置被静默忽略。

## 二、配置步骤（4 步）

### 步骤 0：确认权限

需要满足**其中一条**：

- 你是该小程序的**管理员**；或
- 你是该小程序的**开发者**（小程序管理后台 → 成员管理 → 项目成员，角色为「开发者」）；或
- 管理员在「云开发控制台 → 设置 → 权限设置」里给你分配了云开发权限。

> 报错 `登录用户不是该小程序的开发者 (code 10)` = 上面三条都不满足。
> 去 https://mp.weixin.qq.com → 管理 → 成员管理 → 添加成员，把微信号加进来。

### 步骤 1：开通云开发并创建环境

1. 开发者工具打开本项目，点顶部工具栏的 **「云开发」** 按钮（图标像一朵云）；
2. 首次进入会提示开通，勾选服务条款、完成角色授权；
3. 按提示创建环境，**环境名称**填英文（如 `hz-delivery`），等几分钟初始化完成。

> 首次创建的环境自动成为**默认环境**。微信侧最多可建 2 个免费环境。
> 个人主体**可以**用云开发，不需要企业资质。

### 步骤 2：把环境 ID 填进小程序

环境 ID 在 **云开发控制台 → 设置 → 环境 ID**，形如 `cloud1-d2gar70gv5b552827`。

填到 `miniprogram/config.js`（**本项目已填好**）：

```js
useCloud: true,
cloudEnvId: 'cloud1-d2gar70gv5b552827',   // ← 换成你的环境 ID
```

> `useCloud` 上线时**必须为 true**。填错或没填时，小程序启动会在 Console 打
> `[配置错误] config.js 的 cloudEnvId 尚未填写，无法启用云函数通道`。

### 步骤 3：部署云函数

两种方式，选一个：

**方式 A（推荐，命令行）**

```bash
python .workbuddy/tools/deploy-cloudfunction.py --env <你的环境ID>
```

它会先做前置检查（服务端口 / 登录态 / 云环境 ID / 后端可达性），再调用开发者工具 CLI 部署。

**方式 B（图形界面）**

开发者工具左侧文件树 → 右键 `cloudfunctions/api` → **「上传并部署：云端安装依赖」**
→ 选择目标环境 → 等待右下角提示「上传成功」。

### 步骤 4：配置「环境配置」（环境变量 + 超时）

这一步**只能在控制台点，CLI 配不了**（原因见上一节）。

好消息是：**不配也能跑。** `index.js` 内置了
`FALLBACK_BACKEND = 'http://221.192.236.175'` 兜底；环境变量配了则**优先于**内置默认值。
所以这一步是"可选的正确做法"，而不是卡点 —— 之所以保留兜底，就是因为漏配一次环境变量
会把整条免备案通道直接打死。

开发者工具 → **云开发** → **云函数** → `api` → **「配置」** → **「环境配置」**：

**① 环境变量（可选）**

| 变量名 | 变量值 |
| --- | --- |
| `BACKEND_BASE_URL` | `http://221.192.236.175` |

⚠️ 这里是**后端根地址，不要带 `/api`** —— 函数内部会自动拼 `/api` + 请求路径。

**② 超时时间（建议改）**

云函数**默认超时只有 3 秒**，冷启动 + 转发偶尔会顶到上限。
建议改成 **20 秒**，与 `index.js` 内部的 `TIMEOUT_MS`（15 秒）对齐。

保存后云函数会自动重启，约 10 秒后生效。

## 三、验证是否配通

### 自检 1：云函数能不能连上后端

开发者工具 → 云开发 → 云函数 → `api` → **「云端测试」**，测试参数填：

```json
{"method": "GET", "path": "/client/auth/mode"}
```

期望返回：

```json
{"code":0,"msg":"ok","data":{"mode":"name","codeRequired":false,"nameRequired":true,"maxFail":5,"lockMinutes":10}}
```

- 返回 `code:0` → **通了**；
- 返回 `云函数转发失败：...` → 看下一节的排查表；
- 报 `-501000` / `FunctionName not found` → 云函数没部署成功，回步骤 3。

### 自检 2：小程序端的完整链路

重新编译小程序 → 用名单里的账号登录（手机号 + 姓名）→ 能进首页并看到套餐列表，即全通。

> 名单测试账号见 `db/init.sql` 的 `t_grantee` 表，例如 `13800138000 / 张明远`。

### 自检 3：本地离线自测（不用部署也能验）

```bash
python .workbuddy/tools/test-cloudfunction-contract.py
```

它用 Node 直接加载**与云端完全相同的** `cloudfunctions/api/index.js`，喂入小程序真实发出的
全部调用（登录、订单、轨迹、query 传参、token 透传、异常兜底），断言转发结果正确 ——
**36 项断言**，可在上传前就发现配置错误。

### 自检 4：模拟器里的端到端验证（最接近真机）

云函数**部署成功 ≠ 通道可用**。下面这套会在**真实模拟器**里发请求，同时覆盖
「小程序 → 云函数 → 后端」和「页面 → `utils/api.js` → 云函数 → 后端」两层：

```bash
# 1) 先开启自动化（该命令会常驻，9420 是自动化 ws 端口）
#    注意必须用 cli.bat：用 node 直接跑 cli.js 会算错用户数据目录
cd "<开发者工具安装目录>"
./cli.bat auto --project "<项目根>" --auto-port 9420 --trust-project

# 2) 另开一个终端跑验证
cd "<项目根>"
NODE_PATH="<node workspace>/node_modules" node .workbuddy/tools/verify-cloudfunction.js "<项目根>"
```

**9 项断言**，其中最有价值的一条是"打开首页并断言渲染出真实姓名 / 单位 / 公告" ——
它能证明小程序**自己的请求层**（`utils/api.js`）走的是云函数通道，
而不是只有裸 `callFunction` 能跑。

## 四、出错排查表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `登录用户不是该小程序的开发者 (code 10)` | 当前微信号没有该小程序的权限 | 让管理员在公众平台「成员管理」加你为开发者 |
| 小程序启动报 `cloudEnvId 尚未填写` | `config.js` 没填环境 ID | 回步骤 2 |
| 报「云函数调用失败：请确认已部署云函数 api」 | 云函数没部署 / 名字不是 `api` | 回步骤 3，确认函数名与目录名一致为 `api` |
| 云函数返回 `云函数转发失败：请求后端超时` | `BACKEND_BASE_URL` 不对或后端不可达 | **云函数在腾讯云侧运行，访问不到你的 localhost / 内网 IP**，必须是公网可达地址 |
| 云函数返回 `后端返回的不是 JSON` | `BACKEND_BASE_URL` 带了 `/api`，或指到了非后端地址 | 改成纯根地址，如 `http://221.192.236.175` |
| 真机打开白屏 / 一直加载 | 云环境 ID 填错，或手机没联网到云环境 | 用「自检 1」确认云函数，再看真机 Console |
| 改了后端地址不生效 | 环境变量改完没等重启 | 保存后等 10 秒，或去云函数页点一次「重新部署」 |
| 报 `Cannot find module 'wx-server-sdk'` | 代码里硬 `require` 了该 SDK，而云端没装依赖 | 本仓库已改为**可选加载**；若被改回去，请恢复 `try/catch` 或改用「云端安装依赖」部署 |
| 部署报 `当前函数处于Updating状态，无法进行此操作` | 上一次更新还没落地，**不是**配置错误 | 等 30 秒重试；`deploy-cloudfunction.py` 已内置自动重试（6 次） |
| 云函数返回 `云函数未配置后端地址` | `BACKEND_BASE_URL` 与内置默认值同时为空 | 检查 `index.js` 的 `FALLBACK_BACKEND`，或去控制台配环境变量 |
| 云函数偶发超时（约 3 秒被掐） | 云函数**默认超时就是 3 秒** | 控制台「环境配置」把超时改为 20 秒 |
| 部署后环境变量"消失"了 | 环境变量属于「环境配置」，与代码是两份配置 | 重新部署代码不会改环境变量；若确实没了，去控制台补一次 |

## 六、这条路线的代价（如实说明）

1. **多了一跳**：请求经过腾讯云云函数再转发到后端，比直连多几十毫秒延迟；
2. **多一个依赖**：云函数挂了小程序就用不了，而直连只需后端活着；
3. **免费额度有限**：出流量是主要消耗项，长期运营要留意账单；
4. **调试稍麻烦**：出问题要先判断是"小程序→云函数"还是"云函数→后端"哪一段挂了。

**如果你后续能拿到已备案域名**，把 `miniprogram/config.js` 的 `useCloud` 改回 `false`、
把 HTTPS 域名填进 `backendDebugUrl`，并在小程序后台登记服务器域名即可切回直连 ——
**业务代码一行都不用改**（所有请求都收敛在 `miniprogram/utils/api.js` 这一个文件里）。
